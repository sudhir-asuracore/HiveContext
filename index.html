01 / THE AGENT MEMORY TAXONOMY

Local Agent Memory vs. HiveContext Procedural Memory

Agent memory can be described as 4 distinct parts based on their roles: Short-Term, Semantic, Episodic, and Procedural. While individual agents manage local working state and session history, HiveContext powers the collective intelligence layer—sharing approved procedural intelligence across all agents so entire engineering teams operate as a unified, smarter brain.

Memory Dimension Storage Layer Scope Purpose & Engineering Role
Procedural Memory (HiveContext) CockroachDB + FastMCP Multi-Agent / Entire 10+ Team "How does our team write code, handle incidents, structure APIs, and make architectural tradeoffs?"
Isolated AI Agents (No Collective Memory)

⚠️ Mid-Sized Product Team: Linear Token Multipliers

When a team of 10 engineers each prompt frontier LLMs across separate sessions without a shared memory layer:

Token Burn Equation:
(X tokens exploring ADRs & rules + Y tokens hitting known pitfalls) × N agents × S sessions = Massive redundant token spend
  • 💸 Redundant Exploration: Every agent re-derives architectural guardrails, queries the entire repo for patterns, and spends thousands of tokens rediscovering known decisions.
  • 🔄 Repeated Failure Cycles: An infrastructure bug or nuance resolved by Engineer #1 on Monday is re-encountered and re-debugged by Engineer #5 on Thursday.
  • ⚡ Architectural Drift: Independent agents introduce conflicting conventions, divergent frameworks, and fractured code styles across the codebase.
HiveContext Procedural Intelligence

🐝 With HiveContext: Reusable Context & Strict Consistency

A single governed memory ledger stores trusted ADRs, conventions, infrastructure specs, and post-mortems:

Procedural ROI Equation:
1 validated entry in CockroachDB → Single-turn RAG retrieval (< 200 tokens) across all 10+ agents = Linear cost reduction
  • 🛡️ Guaranteed Consistency: Approved coding standards, guardrails, and architectural choices are injected directly on the first turn of every agent task.
  • 🎯 Zero Recurring Mistakes: Incident post-mortems and infrastructure gotchas are shared globally—preventing repeated trial-and-error debugging cycles.
  • 📉 Dramatically Lower Token Bills: Eliminates lengthy prompting iterations, full codebase AST diff scans, and painful undo-redo-fixing loops across the team.

06 / AGENT INTEGRATION

Connect Any MCP-Compatible Client

Add the HiveContext server configuration to your AI coding assistant configuration file.

Antigravity / Claude Desktop Configuration (~/.mcp.json) 
{
  "mcpServers": {
    "hivecontext": {
      "serverUrl": "https://<your-lambda-url>.lambda-url.<region>.on.aws/sse",
      "headers": {
        "Authorization": "Bearer <your-mcp-secret-token>",
        "X-HiveContext-Tenant": "default"
      }
    }
  }
}
